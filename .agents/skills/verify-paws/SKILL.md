# Verify Paws

## Contract

State the claim before testing: given a particular epic, agent script and failure, which observable state, comment, evidence record and Git ref must result? A green unit suite alone does not prove an epic is safe to merge.

Read `AGENTS.md`, `package.json`, `scripts/verify-local.ts`, `test/local/instance.ts` and `test/local/probes.ts`. Inspect the diff and source commit. Install locked dependencies if needed, using an isolated temporary HOME and KYOTOAGENT_ROOT together.

## Run

Use Linux with Bun 1.4.2+, Git, Python 3, OpenSSL 3 and GNU `timeout` available. From the repository root, use a tracked background task:

```sh
bun --no-env-file scripts/verify-local.ts check
```

`bun run verify:local check` is the package shortcut. The direct command also prevents Bun loading a repository `.env` before the launcher starts.

The launcher creates a fresh `paws-verify-*` temporary directory, checks resolved paths, passes an explicit credential-free environment, and sets HOME, KYOTOAGENT_ROOT, PAWS_HOME, TMPDIR and XDG directories together. It isolates Git configuration and disables desktop Secret Service access. It never invokes a real coding agent or real login.

`check` runs lint, formatting, both TypeScript checks, the full existing test suite, dashboard build and Markdown links, then the behavioral audit. It preserves each command's exit code and log. A prerequisite failure stops execution. Behavioral failures produce exit 1; read `observations.json` to distinguish product failures from a harness exception. Keep failing assertions enabled and rerun after the corresponding product fix.

For the behavioral audit without repeating the suite:

```sh
bun --no-env-file scripts/verify-local.ts audit
```

## Runners dashboard

Run `bun run build:status`, then `NODE_PATH=/absolute/path/to/playwright/node_modules node test/local/runner-dashboard-browser.cjs /absolute/path/to/bun` with `TMPDIR` on a disposable local volume. The driver launches a credential-isolated normal Paws instance with direct HTTPS, persisted owner/member/stale sessions and the actual coordinator mTLS listener. It checks empty and failed states, keyboard pairing, signed connection/sign-in commands, stored health receipts, pause/resume/drain/revoke, duplicate-click prevention and member/recent-login/CSRF denials. Dispatch a parent render while editing and confirm the same form node survives. Inspect another host while editing a health check: agent, model and effort must survive, and submitting without refilling must deliver those exact values in the signed command. Fail only the health-detail request after inspecting another pairing: administrator controls and the pending inspection must remain, then recover after retry. With two paired hosts, failed refreshes retain receipts for the same host; selecting the other host must clear those receipts even when its health request fails. Revocation must return HTTP 403 or the listener’s connection reset over the previously working certificate-verified runner connection, while a separately approved control certificate still returns 200 from that listener. Timeout, parsing and other network errors must fail the proof. Capture desktop at 1440 pixels and mobile at 390 pixels; preserve the printed proof directory, observations and both images, keeping generated private keys out of published artifacts. Linear installation and membership reads and health result contents are scripted; browser routing blocks hosted requests.
