# Paws dashboard design

## System

The dashboard uses [Neobrutalism components](https://www.neobrutalism.dev/docs). Copy-in components live under `src/web/src/client/ui`; their upstream MIT license is retained there. Tailwind 4 builds the stylesheet from `theme.css` and the component and layout utilities. Radix Themes is not used.

The palette follows the landing page: lavender canvas, paper panels, near-black outlines, and orange actions. Dark mode uses deep lavender surfaces and light text with the same orange accent and structural borders. Five-pixel radii, bold headings, and four-pixel offset shadows stay with the Neobrutalism components.

## Layout

The dashboard is an operational surface. A 256px desktop Sidebar stretches to the full document height, with viewport-sticky, independently scrollable navigation exposing thirteen pages in Work, Manage, and Settings groups and one current-page indicator. On mobile, the same navigation opens in a modal Sheet, closes after selection, supports Escape, and restores focus. A sticky toolbar names the current page and keeps appearance available. Overview is two columns on wide screens and one on mobile. The main column holds Needs you, then In progress; the side column holds Queued, Intake, Recently merged and Last 24 hours. Each section heading carries its count. Attention rows show an issue, a reason, and a named next action. In progress rows show the issue, the issue page's phase pill, its reason, and the runner and active time, ordered by phase.

Buttons, inputs, selects, tabs, and navigation links share a 44px control-height token; wrapping content can grow rather than clip. Content uses consistent section gaps and card padding, with detail grids and boards adapting to their available container width. Mobile sheets and dialogs fit the dynamic viewport and scroll internally when needed.

## Behavior

Appearance defaults to the operating system and supports persistent Light and Dark overrides. The root document owns appearance so portaled dialogs and native controls follow the same theme. Issues uses a filterable list with All, Active, Needs attention, and Done filters. Runs opens an index. The issue page uses a toolbar breadcrumb, an issue/title/run header whose pill names the current phase, then one bordered journey card: a full-width stepper through Queued, Implementing, Visual review when there is one, Checking, the fix the agent is on (Fixing merge conflicts, review comments or CI; Fixed with a round count afterwards), Waiting to merge and Done, above a Now panel that says what is happening and why. Questions and decisions follow. Closeout, Review findings, Rules, Risk, Fix rounds, Pull request and merge, Timeline and Run details then fold into one-line rows with a summary; a row opens by itself while it holds a pending decision, and Closeout attempt buttons sit inside the open Closeout row. The issue header carries the pull request and related issues as facts. An accepted attempt folds its passing checks into one row; a failing one lists every check. State changes, skills and hooks fold under one Run details row. Opened, it shows bordered paper panels: the state changes as a vertical timeline (time, a dot in the state's time-bar color, from → to, then the reason and event in plain words), where repeated back-and-forth state changes read as one line with a count; beside it on wide screens, the facts and a list of skills with their versions and hooks with their trigger. Sections without anything to show are left out. Conversations retain a labeled native selector. The toolbar names the current page; its accessible H1 stays in the content region. Overview counts current issues rather than historical runs, keeps attention issues separate from active execution, and lists every open issue without a cap. Queued rows say what each issue waits for: a blocker, a hold or its place in line. Recently merged shows the last five merged issues with their pull request and merge time. Its phase comes from the same `journey()` as the issue page, so both always agree.

Native Select and Input components preserve form names, labels, validation, and the existing FormData controllers. Native checkboxes retain label activation. Each page has one H1 and its own empty state. Missing deep-link targets show a recovery choice instead of silently opening another item. Session creation belongs to Conversations. The Settings sidebar group links directly to five separate pages: Agents, Integrations, Workspace access, Your account, and Audit history. Workspace GitHub installation and connection health belong to Integrations; personal GitHub credit and sign-out belong to Your account. Admins sign in with GitHub before choosing an App installation, browsing repositories, and matching each repository to named Linear teams. The searchable, paginated picker preserves multiple team selections and keeps its save action below a bounded list. The control plane verifies access and saves mappings with installation activation atomically; credentials stay on the server. A runner card leads with its name, one status line, a quiet version, OS and seen line, and Pause. Ruled sections follow in a fixed order: Slots lists each busy slot with its issue, phase and elapsed time and folds free slots into one row; Agents shows each agent's sign-in state with usage gauges per limit window, their reset time and the age of the reading, dropping windows that have reset since; Host shows CPU, memory, disk and load against the core count. Gauges reserve their label and bar rows so bars in a row line up, fill lavender and turn orange when high, and host gauges fade to gray once older than two heartbeats. Concurrency, sharing, the copyable ID, Drain and Revoke sit in a separate Settings card. Dynamic markup is translated into the shared component language in `theme.tsx`; polling preserves document and bounded-log scroll positions.

## Direction contract

THESIS: Preserve Paws's operational workflows while fully replacing the previous visual system with the user-selected Neobrutalism library.

OWN-WORLD: Lavender canvas, paper panels, orange actions, high-contrast solid borders, offset shadows, bold type, shared light and dark tokens, and visible native form affordances.

STORY: See what needs attention, inspect work and evidence, then manage execution settings.

FIRST VIEWPORT: A full-page, grouped sidebar with viewport-sticky navigation and a sticky page toolbar frame the status controls and page content. Mobile replaces the sidebar with a menu Sheet. Overview leads with attention and work sections; detail pages lead with a stable heading and route-specific navigation.

FORM: User-pinned Neobrutalism component system, confirmed with its Tailwind and shared-token setup. All existing features and Light / Dark / System appearance remain available.

FINISH: Inspect desktop and mobile captures in both themes, exercise controller interactions, run repository checks, and run the required read-only reviews.
